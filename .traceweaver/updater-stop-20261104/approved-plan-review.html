CHANGED

Only this review and its evidence manifest were created. Proposed scope is appropriate with the amendments below; implementation and production execution remain subject to owner approval for the Proxy component.

VERIFIED

Frozen DockerEngine uses a 15-second transport timeout and computes stop grace as timeout minus two (13 seconds). Raising the global timeout would also raise grace, preserving the inadequate two-second allowance. The request wrapper converts OSError into MigrationError with the original exception as its cause. replace_container discards all non-UpdateError details. It marks started_stop before calling stop, so stop failures already enter automatic recovery. Disconnect happens immediately after stop, before rename. Result dictionaries are persisted by the worker.

Diagnosis records SIGTERM to stop event duration 15.110771697 seconds, forced kill after approximately 13 seconds, no candidate rename/create/start, and original restart. These are retained incident evidence, not a new independent observation of live health or data counts.

CLAIMED

A stop socket timeout is strongly supported, not established: the exception was lost, and a following disconnect failure remains possible. The repair addresses a demonstrably inadequate timeout relationship but cannot claim to have proved the historical exception or eliminated every cause.

  1. Keep the production stop grace at 13 seconds; introduce a stop-specific transport budget with explicit bounded acknowledgement headroom, e.g. 13 + 15 = 28 seconds. Pass this only to that request. Preserve other request timeouts and readiness deadlines. Do not mutate a shared engine timeout or extend grace when adding response headroom. Define behavior for existing nondefault timeout callers before coding.
  2. Record an allowlisted operation phase set immediately before each fallible mutation (including stop and disconnect), and a bounded allowlisted exception category. Merely recording type(error).__name__ yields MigrationError for socket failures; classify its known cause, such as TimeoutError, without serializing text, paths, payloads, arguments or tracebacks. Unknown classes map to a fixed generic category.
  3. Freeze the primary failure phase/category before recovery starts. If recovery fails, preserve those primary diagnostics and separately record a recovery phase/category; retain current failed/rolled_back/recovery_required semantics. Diagnostic construction must not throw or interrupt recovery. Keep identity, policy and native recovery guards intact.
  4. Reuse existing replacement and recovery tests. Add the smallest cases proving stop timeout classification through MigrationError.__cause__, distinction from disconnect failure, secret-bearing exception text exclusion, and retention of primary failure when recovery fails. Verify added fields survive actual worker job persistence.
  5. Use a real local Unix-socket HTTP boundary for representative delayed acknowledgement: original default request times out before a response at more than 15 seconds; revised stop succeeds with the same 13-second grace; a request exceeding the new bounded budget still fails and enters recovery. A shortened timing version may serve regression CI, but preserve one representative full-scale proof. Include a disposable Docker staging update/recovery against the frozen repair image to exercise daemon behavior, image identity and health recovery. No production retry to obtain missing diagnostics.
